## 1. The data (`daniel dataset boson + day/`, 17 sessions of 2026-10-06)
- Per session: clean 4K day `.ts` (+ KLV), `_osd.ts` (1080p day with the live overlay and a wall-clock stamp), `_thermal.ts` (640×512). 10_06_17 and 10_06_30: day/osd files are 0 bytes → unusable. 15 sessions usable.
- Usable windows (Daniel, min.sec): 08_58_15 from 4:46; 09_09_29 first 30 s; 10_15_59 first 1:30; all others whole. About 9.5 min of usable thermal overall.
- **True frame rates:** thermal headers say 60/120 fps but real rate = frames/duration = 30 (60 for 09_58_37, 10_00_40). ffmpeg's default decode duplicates frames (4× on the 120 fps headers: 1,273 real frames → 5,060). `.ts` has no frame count. Fix: lossless remux to mp4, decode with `-fps_mode passthrough` or cv2 sequentially; patched `video_pairs.ffmpeg_frames` and `verify_stream_sync`.
- **Overlays burned into the thermal stream:** a solid green square marker, a green crosshair reticle, occasionally a green box; 2–73% of frames per session (`thermal_overlay_flags.py`, pure green G>180, R,B<100). Chroma speckle on terrain is not overlay (first version of the detector flagged it). Overlay frames are excluded from training and pairs.

## 2. Sync and registration
- **Sync** (ego-motion): thermal is 120–154 ms behind day, constant (10_xx sessions agree within ~1 frame); the 09_06/09_07/09_09 sessions show a 1–6 ms/s drift that equals their container fps error (30.19 vs 30.0). Sync failed on 08_58_15 (2 clear windows, −143 ms), 09_58_37, 10_00_40, 10_05_11, 10_12_48, 10_15_28 (low motion): used the measured or median offset.
- **New rig geometry:** the thermal view lies *inside* the day view (≈ 3.3 day px per thermal px at the registered scale 0.30; old rig had the day view inside the thermal). `calibrate` assumed the old layout (every candidate skipped): added `coarse_search_inside`.
- 8 sessions calibrated themselves; **their solved transforms agree: 26 segments over 6 sessions give scale 0.3005 ± 0.001, rotation 0.15° ± 0.1, translation (−253, −41) ± 2 px** (the rig is rigid). Sky-dominated clips cannot calibrate (edges need structure), so those use the median transform (`make_shared_registration.py`: 08_58_15, 09_06_16, 09_07_28, 09_09_29, 09_58_37, 10_00_40). Visual check (RGB | thermal | RGB edges on thermal) on six sessions incl. shared-H ones: horizon, roads and path junctions coincide. Every extracted pair is still alignment-checked.
- Added calibration time windows (`--t-min/--t-max`) so long sessions are sampled in their usable part.

## 3. Labels: two independent detectors on a registered pair
- RGB: production day model (`yolo26s_20260921_145030_rgbcurrent.pt`), tiled 640 px / 0.2 overlap (SAHI-style, 32 tiles per 4K frame), every 3rd day frame. THERM: current best thermal model (YOLO26s-P2 seed 1).
- Per thermal frame (`build_boson_labels.py`): **pos** = RGB candidate (uav/airplane ≥ 0.10) and THERM (≥ 0.20) on the same object, box = the thermal box; **hard** = RGB ≥ 0.50, THERM silent; **neg** = no RGB ≥ 0.25 and no THERM ≥ 0.10; **skip** otherwise. Precision of the pos rule on hand-reviewed 06-23 s1 boxes was 99.5%.
- First sessions: 09_06_16 → 210 pos / 341 hard / 262 neg / 410 skip of 1,223 frames. Visual check: pos boxes sit on real fixed-wing drones down to a few pixels; hard boxes sit on empty haze (probably RGB false alarms or thermal-invisible targets): not used for training, queued for review.
- **Held-out test sessions: 08_58_15 and 10_15_59** (never in any training set). Caveat: their pos/neg labels come partly from the thermal model, so they cannot rank models against each other; the unbiased test on them is **human labels (tomorrow, queue page)**.

## 4. Generator pairs
`make_boson_pairs.py`: `extract` → drop overlay frames and out-of-window frames → each pair cut into two 2:1 crops (640×317, top/bottom) so the 512×256 generator input is not squashed. ~700 crops over 15 sessions. `data/diff_pairs_boson`: old six sources (same recipe as diff_pairs_all) + Boson sessions; train 1,512 pairs (+ oversampled terrain/mixed copies), val 177, test 550 incl. **218 pairs from the held-out sessions**.

## 5. Pre-registered criteria (written before any new training finishes)
**Detector M** = YOLO26s-P2 from the RGB weights (as L) on `thermal-4-bosonP` = thermal-3-pasteG + the exported Boson labels (train/val) + pastes on new *real* backgrounds from clean-negative frames. Baseline L = `pasteG_y26sp2`, 3 seeds. Scored with `score_models.py`, mean recall FF 1–25%, seed means.
- **Adopt M** if on 0708_sky, 0730_sky and 0708_all its mean is no more than max(L's seed spread, 3 pp) below L's mean (non-inferior on old data), **and** the human-labeled held-out sessions (when available) show a gain.
- **Reject M** if any of the three drops by more than that. Old sets measure regression, not the target (new rig); this is stated up front.
**Generator**: continue the ControlNet from `diff_cn_all/best` on `diff_pairs_boson`. On the 218 held-out Boson pairs: **GO** only if translator L1 ≤ 0.85 × the linear-colour baseline L1 (the earlier C2 rule; baseline fit on train) and the old test (230 pairs) L1 does not get worse by more than 5%; else NO-GO. The old model's result on the same held-out pairs is the control.
